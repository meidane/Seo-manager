# personal/ — فضای شخصیِ خصوصی (فقط یوزرِ admin)

داشبوردِ خصوصیِ `admin`. **بالای صفحه = تقویمِ مشترک** (همان ماژولِ `/calendar/`؛ دوبار کد
نزن) + پایین‌تر: هبیت ترکر، اهداف، یادداشت‌ها، ثانیه‌شمارِ عمر.

## بالای صفحه = تقویمِ مشترک (این تغییر — «کلِ بالای شخصی = تقویم»)
`templates/personal/index.html` فقط پارشالِ `calendarapp/_calendar.html` را include می‌کند
با `cal_fixed_assignee=<id همکارِ خودم>`، `cal_undated_default=True`، `cal_quick_add=True`،
`cal_personal=True`. یعنی:
- تقویم فیکس روی خودِ کاربر است (فیلترِ همکار مخفی).
- پنلِ **«تسک‌های بدون تاریخ»** باز است = **جایگزینِ اینباکسِ قبلی** (هر تسکِ بی‌تاریخِ من).
- فیلدِ **افزودنِ سریع** روشن است و تسکِ سریع در **پروژهٔ شخصی** ساخته می‌شود
  (`calendar_quick_add` با `personal=1` → `personal.api._create_personal_task`).
- تاریخ‌دارکردن با **درگِ** آیتمِ بدون‌تاریخ روی یک روز.
- context از `calendarapp.views.calendar_base_context(request)` می‌آید (منبعِ واحد، مشترک
  با `CalendarView`).
- **حذف شد:** اینباکسِ قدیمی، گریدِ ۷روزهٔ هفته، نمودارِ هفتگیِ باکسِ روزانه، نوارِ بازهٔ
  سراسریِ بالای صفحه (`_daterange_bar`)، و سلکتورِ هدفِ هر ردیف (`_goal_select.html`). JSِ
  مربوطه از `static/js/personal.js` پاک شد (فقط هبیت/اهداف/عمر + `makeSortable` ماند).
  اندپوینت‌های `ptask_*`/`DailyPlan` حالا بی‌استفاده‌اند (`docs/CLEANUP.md`).

## معماری (مهم — بدونِ سیستمِ موازی)
- **تسک‌های شخصی = `tasks.Task`** با نوعِ «شخصی» (`TaskTypeDef`ی که کاربر دستی می‌سازد،
  `PERSONAL_TYPE_NAME='شخصی'`)، در **پروژهٔ شخصیِ خودکارِ همکار** (`Project.personal_owner`).
  چون آن پروژه فقط برای خودِ همکار دیده می‌شود (`projects/access.py`)، این تسک‌ها خودکار
  در **تقویم/لیست هم فقط برای admin** ظاهر می‌شوند — هیچ مدلِ `PersonalTask`ی نداریم.
- **done/حذف/تغییرِ تاریخ/تایمر/ویرایشِ کامل** از همان `tasks/api.py` می‌آیند (reuse):
  `/tasks/api/<id>/status|timer`, `PATCH/DELETE /tasks/api/<id>/`، و کلیک روی عنوان →
  `openTask(id)` (مودالِ کاملِ تسک، از `tasks.js`). **ساختِ سریعِ** تسکِ شخصیِ بی‌تاریخ از
  پنلِ «تسک‌های بدون تاریخ»ِ تقویم می‌آید (`calendar_quick_add` با `personal=1` →
  `personal.api._create_personal_task` که دیفالت‌های شخصی را سرورساید تحمیل می‌کند).
- `api.personal_context(request)` = `(همکار، پروژهٔ شخصی، نوعِ «شخصی»)` منبعِ واحد. اگر
  نوعِ «شخصی» نبود، صفحه یک نوتیسِ راهنما نشان می‌دهد (`setup_needed`).
- عادت/هدف معادلی در تسک ندارند → مدلِ اختصاصیِ همین اپ (`Habit/HabitLog/Goal`)، اسکوپِ `user`.
- **اهداف (ساده، فقط شخصی):** `Goal` فیلدِ `color` (برای آیکنِ 🎯) + توضیحاتِ HTMLِ TinyMCE
  (پاکسازی با `clean_html`) دارد. وصلِ تسک↔هدف با مدلِ `GoalLink(goal, task OneToOne, order)`
  — **مدلِ `Task` دست‌نخورده می‌ماند**. API: `task_goal` (وصل/قطع)، `goal_detail` GET (متا+تسک‌ها)،
  `goal_add_task` (تسکِ وصل‌شده)، `goal_reorder`. UI: کلیک روی هدف → مودالِ جزئیات (توضیحات +
  تسک‌های مرتبط + افزودن + جابه‌جایی). سلکتورِ هدفِ هر ردیف (`_goal_select.html`) حذف شد (با
  اینباکس/گریدِ قدیمی). درگ‌ودراپِ قابلِ‌استفادهٔ مجدد: `personal.js: makeSortable(list, sel, onDrop)`.
- **`DailyPlan`/اندپوینت‌های `ptask_*`** بعد از جایگزینیِ بالای صفحه با تقویم بی‌استفاده
  شدند (`docs/CLEANUP.md`) — نه حذف‌شده، نه فراخوانی‌شده.
- **درصدِ عادت** = روزهای انجام‌شده (هر روز، حتی غیرِ هدف) ÷ روزهای هدفِ هفته (بی‌روز=۷)، سقفِ ۱۰۰.
  یعنی «تعدادِ روزِ انجام» مهم است، نه فقط روزهای هدف.

## امنیت
- **گیت = `access.py: admin_only`** (روی ویو با `method_decorator`، روی هر API). فقط
  سوپریوزر **و** `username=='admin'` (`ADMIN_USERNAME`) — وگرنه **۴۰۴**. عادت/هدف با
  `get_object_or_404(..., user=request.user)`. تسک‌ها با گیتِ پروژهٔ شخصیِ خودِ `tasks/api`.
- لینکِ سایدبار هم `{% if request.user.is_superuser and request.user.username == 'admin' %}`.

## باکس‌ها (`views.PersonalDashboardView`)
بالای صفحه = تقویمِ مشترک (بالا، بخشِ «بالای صفحه = تقویمِ مشترک»). پایین‌تر فقط این‌ها
مانده‌اند (ویو سبک شد — دیگر محاسبهٔ اینباکس/گریدِهفته/نمودار و نوارِ بازه نیست):
- **هبیت ترکر** (هفتهٔ **جاری**، بدونِ ناوبری — چون بالای صفحه حالا تقویم است، نوارِ بازهٔ
  قبلی حذف شد): **همه‌ی روزها کلیک‌پذیرند** (فقط آینده disabled)؛ روزهای هدف (`weekdays`)
  پررنگ‌تر (`.active`). درصد = رعایت‌شده / روزهای هدفِ گذشتهٔ همان هفته.
- **اهداف**: تایم‌لاینِ «چند روز گذشته» + مودال (ویرایش/جزئیات در `personal.js`).
- **یادداشت‌های شخصی** (پایین).
- **عمر**: شمارشِ زندهٔ باقی‌مانده «Y سال و D روز و …» (هارد‌کد: ۲۸ تا ۷۵؛ فرانت از `data-*`).

## یادداشت‌های شخصی (`PersonalNote`)
باکسِ «یادداشت‌های شخصی» در داشبورد (کنارِ اهداف، ۵۰٪): عنوانِ **اختیاری** + متنِ
**TinyMCE** (پاکسازی `clean_html`)، چندتایی، **جدید/تازه‌ویرایش بالا**
(`ordering=['-updated_at']`)، با **سرچِ سمتِ کلاینت**. **ادیتِ اینلاین، بدونِ مودال** (خواستِ
کاربر): هر یادداشت یک `input.pn-title-inp` (عنوانِ اینلاین) + `textarea.rich-editor.pn-body-inp`
(TinyMCE، هر کدام `id="pn-body-<id>"`) + دکمهٔ **ذخیره/حذف** درجا دارد. «＋ یادداشت» یک
آیتمِ خالیِ نو بالای لیست می‌سازد و `RichText.init('#'+eid)` را روی همان می‌زند (بدونِ
re-initِ بقیه). API: `note_add` (POST)، `note_edit` (PATCH/DELETE)، اسکوپِ `user`. JS/استایلِ
باکس درونِ `index.html`.

## فایل‌ها
